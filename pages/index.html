About

I work on the geometry side of AI. My main belief is that what looks like reasoning in modern language models is mostly continuous geometric operations on embedding spaces — and that we get more honest, more debuggable, more controllable systems when we treat that fact as load-bearing instead of papering over it with simulated symbolic logic.

That conviction shows up in two places. Sutra is the language I’m building to express programs as straight-line tensor arithmetic with no control flow at all. The interactive tutorials are how I keep myself (and anyone else) honest about what actually happens inside neural networks — you can’t hand-wave a visualization that you have to drag with your mouse.

I also build adjacent tooling: knowledge graph pipelines for Wikidata and Pramana, context-management libraries for AI agents (OpenClaw / claw.py), and SutraDB — a vector database tuned for the kinds of queries Sutra emits.

Flagship Project

📜 Sutra
A geometric tensor programming language.

Every value is a tensor. Every operation is tensor arithmetic in a geometric space. There is no print, no if, no while — branches are continuous weighted blends and loops are geometric rotations. Programs compile to straight-line tensor operations, which makes them GPU-native and end-to-end differentiable by construction.

I’m building the reference compiler (with a PyTorch backend), the IntelliJ and VS Code plugins, the language specification, and the interactive demos — plus SutraDB, the bundled vector database that lives inside the same ecosystem. The name comes from the Sanskrit sūtra, the word used for Pān&dotbelow;ini’s grammar of Sanskrit, the earliest known formal grammar of any language.
